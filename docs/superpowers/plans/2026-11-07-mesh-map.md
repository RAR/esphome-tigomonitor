# Mesh Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Mesh tab on the Pi's Topology page that draws each TAP as a hub with its optimizers around it, every link coloured by that optimizer's measured report loss and raw RSSI.

**Architecture:** A pure, header-only `LinkStats` (shared with the ESP32 tree, unused there for now) counts each optimizer's lost reports from slot-counter gaps and keeps 24 h of 5-minute RSSI averages. `Monitor` feeds it from the poll replies it already walks, plus NetDiag join packets. `/api/mesh` serves it; app.html draws it with hand-built SVG.

**Tech Stack:** C++17 header-only + host tests (g++), cpp-httplib/nlohmann::json in the Linux daemon, vanilla JS/SVG in app.html, `node --test` + Playwright for the UI.

**Spec:** `docs/superpowers/specs/2026-11-07-mesh-map-design.md`

## Global Constraints

- **No new bus frames.** Nothing here sends anything; it only reads what `Monitor::feed` already gets.
- **Pi only:** the tab carries `data-linux-only`; the ESP32 build and UI are unchanged.
- **No identifiers** in the API, fixtures, tests, logs or commits: no MACs, PANs or keys. Tests use the fake prefix `04C05B0000`. NetDiag data bytes 0–7 (a possible network-wide ID) are never stored, logged or exposed. The API identifies optimizers by short address and label only.
- **RSSI is the raw byte** (`PowerReading::rssi`, 0–255, higher is better); never labelled or converted to dBm.
- Tiers (one JS constant): poor = loss > 5 % or RSSI < 80; fair = loss 1–5 % or RSSI < 110; good otherwise; silent = not heard for 600 s.
- `/api/mesh` shape change → `site/screenshots/fixtures.mjs` `piRoutes` updated in the same commit; then `cd site && npm run screenshots`.
- `"loss_method": "slot"`, `"parent": null`, `"parent_confirmed": false` (parent decoding is a follow-up).
- Commits: `git -c user.email=andrew@eiknet.com commit`, types fix/feat/docs/test/…, no attribution trailers.
- Builds and host tests run in Docker: `docker run --rm -v "$PWD":/src -w /src tigod-dev sh linux/scripts/build.sh`. No sudo, no package installs.
- `node --check` the extracted app.html script after UI edits (the site tests do this through the page load; a page error fails them).

## Review Focus

1. **Dusk and night:** optimizers stop reporting for ~12 h; that silence must not count as loss, and the next morning's first report must not add a huge gap. (Task 1, `test_a_long_silence_is_not_loss`.)
2. **Reports delivered two at a time, out of order:** a modular gap above half the wrap (> 24,000 ticks) with a short wall-clock gap is a reordering, not 47,600 ticks of loss. (Task 1, `test_out_of_order_is_not_loss`.)
3. **Daemon restart mid-day:** counts start at zero and the sparkline is empty; the API must still list every optimizer heard since, and the UI must render empty sparklines as "no history yet", not as a flat line at 0. (Task 1 `test_empty_ring_is_all_missing`; Task 4 `mesh: empty history`.)
4. **An optimizer heard only before midnight:** after the day rolls, its `reports_today` is 0; loss must show "—", not NaN or 0 %. (Task 1 `test_midnight_resets_today`; Task 4 `mesh: no reports today`.)
5. **No TAP reply heard yet** (a fresh start, or the Pi listening to a quiet bus): `/api/mesh` returns empty arrays and the tab shows its empty state with no page error. (Task 3 e2e; Task 4 `mesh: empty`.)

**Interfaces:**
- Produces, in namespace `esphome::tigo_monitor::link`:
  - `uint32_t slot_ticks(uint16_t slot)` → `(slot >> 14) * 12000 + (slot & 0x3FFF)`; `WRAP_TICKS = 48000`, `BIN_TICKS = 400`, `BUCKET_S = 300`, `BUCKETS = 288`, `LONG_GAP_S = 200`.
  - `struct Link { uint16_t tap; int rssi; int64_t last_heard_s; int64_t last_join_s; uint32_t reports_today; uint32_t lost_today; /* private-ish: day, last slot, cadence, ring */ };`
  - `class LinkStats { public: void on_report(const std::string &addr, uint16_t tap, int rssi, uint16_t slot, int64_t unix_s, int day); void on_join(const std::string &addr, int64_t unix_s); std::vector<int> rssi_24h(const std::string &addr, int64_t unix_s) const; /* 288 values, oldest first, -1 = none */ const std::map<std::string, Link> &links() const; };`
  - `day` is any integer that changes at local midnight (the caller passes local YYYYMMDD).

- [ ] **Step 3: Implement `link_stats.h`.** Header-only, no ESPHome/IDF includes (like `tigo_protocol.h`). On a report: roll the day if changed (reset counts and cadence); if there is a previous report with wall gap < `LONG_GAP_S`, take `gap = (ticks − last_ticks) mod WRAP_TICKS`; gap 0 → duplicate (no count); gap > WRAP_TICKS/2 → out of order (no count); else set cadence = max(gap, BIN_TICKS) if it is unset, otherwise min(cadence, that), then add `round(gap / cadence) − 1` to lost. Cadence starts unset each day, so the first gap only teaches it (a loss in the very first gap of the day goes uncounted; say so in a comment). Count the report and record last slot only when it isn't a duplicate or reorder. The ring is 288 `{int64_t bucket; int32_t sum; uint16_t n;}` indexed by `bucket % 288`; a slot whose bucket isn't the requested one reads as −1.

**Interfaces:**
